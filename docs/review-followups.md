# 2026-10-14 全仓审阅后续修复

本批处理此前主仓库全仓 CodeRabbit CLI 审阅的 6 项待办，与头透传、WHAM 和玻璃托盘菜单的原 PR 分开提交。

| 问题 | 修复与验证 |
|---|---|
| 真实验收脚本恢复设置遗漏统一阈值 | settings CLI 支持同时恢复旧五小时/周阈值与可空 windowThreshold；两处恢复共用参数生成，清理失败也执行恢复；验证统一、旧版、非整数阈值往返 |
| 刷新沿用客户端取消令牌 | 等待刷新锁仍接受调用者取消；开始轮换后用独立 60 秒期限完成交换、验证和持久化，然后传播调用者取消；确定性 barrier 验证轮换不中途丢弃 |
| 部署误把持久 refresh_pending 当成主动刷新 | 按 accountAvailability 区分正在刷新、需要重新授权、未知；主动刷新和未知状态继续阻止停止，持久状态保留且提示重新授权；PowerShell AST 提取函数验证三个分支 |
| 原生 refresh 的格式异常未归一化 | JSON、JWT 和账户元数据格式异常转为固定 AuthFailure，标记重新授权并禁止再次使用旧凭据；覆盖 7 种损坏载荷 |
| /usage 单账户失败阻断整个刷新 | 与后台共用 RefreshAllAsync，预期账户故障隔离，调用者取消原样传播；后续账户继续刷新 |
| 后台刷新遗漏 IO/存储异常 | 捕获预期 IO、权限、加密存储故障，下轮可恢复；额度快照不替换为伪零值；固定错误分类通过 status/events 的 quotaRefreshErrors 可见。自动选择保存失败同样保留 owner/epoch，并通过 quotaSelectionError 可见 |

本批模型协议/调度 34/34、安全合成测试 36/36（排除占用固定 3210 的 Local API 集成测试）、UI 11/11 通过；Release 构建通过。部署保护的主动/持久/未知分支和脚本语法均已检查。

当前本机真实代理仍运行旧构建，未执行本批部署；停止代理操作被执行策略拒绝。这里的取消、原生格式和额度故障测试均为合成凭据/受控处理器，不扩大真实多账户 continuation、compaction、refresh 或 Desktop 的验收范围。未进行真实账户刷新或 live 验收脚本执行。

公开仓库后的 GitHub CodeRabbit 首轮完整审阅覆盖初始提交，提出两项超时边界意见，均已修复：发现阶段尚未发送令牌请求的超时/网络失败返回暂时不可用；请求可能已发送后仍按结果未知要求重新授权；轮换后的身份验证超时返回固定 refresh_validation_timeout。新增回归区分发现、交换和验证三个阶段，保持旧令牌不被不确定重用。
