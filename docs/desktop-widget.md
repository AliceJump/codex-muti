# 托盘状态面板（第一版）

状态面板位于右下角 Codex Pool 托盘图标，单击展开透明着色卡片。它只展示代理状态和额度、发送账户激活请求，以及打开 Web，不管理 Codex 会话或执行工具。当前以已认可的独立三态演示为动画基准，真实系统 Acrylic 模糊留待独立验证。

## Windows 11

```powershell
.\scripts\build-and-start.ps1
# 只更新 UI，并自动关闭旧 UI、启动新 UI，不停止代理：
.\scripts\update-ui.ps1 -Show
# 或分开执行：
.\scripts\build-local.ps1
.\scripts\start-local.ps1
# 默认打开 Dashboard；只添加托盘图标可关闭浏览器启动：
.\scripts\start-local.ps1 -Dashboard:$false
```

`build-local.ps1` 将 Daemon、Widget 发布到独立的 `.local/builds/<版本目录>`，不会覆盖正在运行的文件，也不停止或重启进程。`start-local.ps1` 使用最后一次成功构建；已有代理时保留原进程，只启动托盘客户端。让新代理代码生效，需要你先结束模型请求、自己退出旧代理，再运行启动脚本。旧托盘界面可从菜单“退出托盘面板”退出，代理继续运行。

UI 启动脚本将界面安装到固定的 `.local/desktop/Widget`，代理仍从独立版本目录运行。更新界面时先暂存新文件，仅在该固定目录的 UI 已退出时替换；旧文件保留在相邻备份目录，不中止或覆盖正在运行的 UI。托盘图标使用固定 GUID；首次从旧路径迁移可能需要重新拖出图标一次，后续更新保留路径和图标身份，避免每次构建都变成新的系统托盘条目。启动请使用脚本/快捷方式，避免直接从版本目录运行托盘 EXE。

原来的固定目录构建入口也保留：

```powershell
.\scripts\build-widget.ps1
.\scripts\install-widget-shortcut.ps1
.\scripts\open-widget.ps1
```

第一次完整安装先运行 `scripts/build-release.ps1`，生成相邻的 Daemon。之后只更新小组件可用 `build-widget.ps1`，不会发布或重启正在工作的代理。

- 桌面启动入口：**Codex Pool 小组件**。后台启动只添加托盘图标，包括保存过固定状态的面板；单击图标展开，再次单击、按 Escape 或点击外部收起。固定状态和位置在主动展开时恢复。没有代理则启动相邻的 Daemon；已有代理继续工作。`start-local.ps1` / `build-and-start.ps1` 默认同时打开 Dashboard；发行包直接启动也只打开 Dashboard 和添加图标，`--show` 才主动显示账户面板。
- Web 服务随 Daemon 默认启用，地址 `http://127.0.0.1:3210`；不会每次打开小组件都弹浏览器。**打开 Web** 使用单次安全票据建立浏览器会话。
- 默认展示当前账户、启用账户数、进行中的请求数、每账户动态额度窗口、重置倒计时、最近额度更新时间、自动切换状态。
- 详细模式在每个账户卡片中分别显示“今日 Token 用量”，保留该账户上游报告的输入与输出总量；下方小横条按该账户的输入拆为左侧绿色缓存、右侧蓝色未缓存，并分别显示数量和占输入的比率，不合并其他账户。大数使用万／亿缩写，悬停可查看完整数值及报告覆盖率。缓存明细缺失时显示待确认，零输入时不伪造百分比。缓存是输入的子集，不重复相加；上方总量还含输出，这个处理量不表示套餐额度扣减或实际费用。
- 托盘小图标平时显示当前账户的 **5h 等短周期剩余百分比**（也支持 7h、9h；例如 `12` 表示剩余 12%）。周窗口只有耗尽，或自动切换开启且达到实际配置阈值时才优先显示，不因其剩余百分比更低而抢占短周期。悬停显示同一窗口的额度及重置倒计时，附加模型额度保留在详情中。剩余低于 30% 时黄色、低于 15% 时红色，实际耗尽时显示 **X**；离线、数据过期或短周期已重置但未刷新时显示灰色 `—`，不回退成健康的周额度，也不伪装成 0%。
- 托盘数字与悬停文字在同一次系统调用中更新；只有 Windows 接受更新后才缓存显示状态。更新失败后，后续状态轮询会重试相同数据；修改失败不视为图标已移除，避免旧图标仍存在时不断重复添加而卡住旧账户与旧额度。
- Radio 只修改下一次请求的 sticky active account。当前请求继续使用原账户。
- 点击标题栏图钉固定当前面板：保持置顶，点击外部不收起，并允许拖动；再点一次取消固定，回到托盘锚点并恢复失焦收起。胶囊态可通过托盘右键菜单固定/取消固定。不创建第二个窗口或进程，独立悬浮窗及其启动入口已移除。
- 面板展开时临时置顶，以点击的托盘图标为锚点在其正上方居中展开，靠近工作区边缘时钳制位置；顶部没有空间时才改到图标下方。图标位于“^”隐藏区时同样跟随图标位置，快捷键展开使用当前图标位置。支持完整/紧凑/胶囊、系统/浅色/深色；固定后可作为常驻面板拖动。
- 胶囊只显示可见账户名称和右侧上下两条短周期/周额度条；当前账户以强调色背景表示，不显示 Radio 圆点或勾选标记。点击账户切换，自动切换时背景颜色同步。暂停、排空或离线的完整状态保留在悬停说明中。胶囊没有展开、刷新、Web、关闭等按钮，也不显示圆环、标题或底部操作栏；宽度按账户内容收缩，完整名称和重置时间可悬停查看。已禁用的非当前账户不占位置。
- 不可选的胶囊账户采用灰字、淡灰背景和降低透明度，当前账户不可用时也显示灰色；禁止激活，并保留“暂停 / 冷却中 / 需登录”等状态与悬停说明。可选的待命账户保持正常文字颜色。
- 点击托盘或唤醒隐藏面板时，外框与内容一起沿托盘方向轻移 8 DIP 并淡入；首次和再次展开都播放，快速隐藏会停止回调，下次重新展开不会闪现最终画面；托盘按下导致的失焦和随后的选择回调按一次切换处理，不再使用 500ms 点击抑制。高对比度或系统关闭动画时直接显示。三态切换保持场景锚点。未固定时失焦收起；固定时失焦保持显示，Escape、×、Alt+F4 和再次单击托盘仍可主动隐藏。
- 原生透明宿主在三态切换中保持固定大小。可见轮廓、卡片位置和显隐由同一连续弹簧状态驱动，新目标接续当前姿态与速度，快速切换不会丢弃输入。移除旧截图补间、逐帧 SetWindowPos 和切换前后启停 Acrylic 的路径。卡片文字固定字号绘制，按钮保留键盘、读屏名称与完整信息帮助；状态更新直接更新已有卡片，不等待动画结束。隐藏/关闭后停止逐帧回调。系统关闭动画或高对比时直接到达目标。
- 紧凑态宽度为 284 DIP，与完整态 432 DIP 明显区分；每个账户行左侧居中显示名称/状态，右侧用圆环、剩余比例及重置时间展示真实额度窗口，减少卡片高度和横向留白，底部采用小按钮。完整态保留所有额度条、重置时间、Token 与更新时间。胶囊只显示名称及右侧上下两条迷你进度条，分别表示短周期与周额度，未知数据保持灰色，数值及附加额度保留在悬停提示与读屏帮助中。多账户超出可视区时支持滚轮、PageUp/PageDown/Home/End 和键盘焦点自动滚动，空池显示添加账户提示。多账户滚动后的形态切换接续当前滚动位置，短形态暂时无需滚动时仍保留用户的位置，切回长列表后恢复；固定面板靠边展开时自动回到工作区内，画面保持连续。保存的是目标场景的底部中心锚点，动画中关闭或保存也能恢复到所选形态的位置。
- 窗口获得焦点时按 `Ctrl+M` 循环切换完整/紧凑/胶囊模式。固定后的面板可拖动标题栏或胶囊边缘空白区域；显隐快捷键和 Alt+F4 仍然可用。
- `Ctrl+Alt+W` 显示/隐藏小组件。重复后台启动保持隐藏；只有明确的显示操作才唤醒已有界面。
- 数字额度图标的右键菜单集中提供账户选择、开启／关闭自动切换、刷新额度和“打开账户管理与用量”，并保留显示／隐藏、固定、系统图标设置。状态每 3 秒通过有 5 秒超时的 `/status` 请求更新，不依赖长期事件流；刷新额度和打开 Dashboard 在首次状态尚未到达或断线时仍可主动尝试。各控制请求独立读取本地授权，失败时解除操作锁并在隐藏状态下发送通知；部分账户刷新失败会明确提示保留旧数据。“启动代理”（离线）可拉起代理服务及独立控制图标；在线时显示“打开代理控制”。服务操作中的账户／额度选项暂时禁用，代理离线时启动按钮仍可用。
- 隐藏保留托盘图标，托盘“退出账户面板（代理继续运行）”只退出客户端。代理、Web 服务和其他客户端继续运行。另一个代理图标可通过“打开账户浮窗”重新启动或显示此客户端，既有进程直接复用；单纯显示面板不会重新启动已关闭的代理。
- 面板只有一个实例和一个托盘图标。**×** / Alt+F4 隐藏当前面板，不停止代理；再次单击托盘或启动入口可唤醒同一面板。
- `widget.json` 保存布局、主题、固定状态和固定位置。旧独立浮窗的 `window.json` 不再使用。
- 小组件不显示已禁用的历史账户；这些账户仍可在 Web 面板管理。未知额度显示 `—`，离线时禁止账户切换，保留的快照由离线状态提示。

托盘图标可能收进右下角 **^** 的隐藏图标区域。是否常显由 Windows 和用户的选择决定，与开发模式本身无关；可在“设置 → 个性化 → 任务栏 → 其他系统托盘图标”开启，或拖到任务栏。托盘右键菜单提供“任务栏图标显示设置”入口，不强改系统偏好。微软说明，升级时只有 [EXE 路径与图标 GUID 保持不变](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)，才能保留关联设置；移动整个仓库仍可能丢失原偏好。Explorer 重启后客户端重新注册同一图标。本面板使用独立托盘入口，不嵌入 Wi-Fi/音量快捷设置，也不是 Windows Widgets 面板提供程序。微软的 [NotificationIcon 示例](https://learn.microsoft.com/en-us/windows/win32/shell/samples-notificationicon)支持这种 rich flyout 形式。

## macOS 客户端原型

原生源码位于 `src/CodexPool.Widget.Mac/CodexPoolWidget.swift`，使用 SwiftUI、AppKit 原生背景材质和菜单栏入口，最低系统 macOS 14。菜单栏图标弹出账户状态卡片，并提供浮窗和 Web 入口。状态更新任务独立于窗口生命周期。

在 Mac 上构建并预览：

```bash
bash scripts/build-widget-mac.sh
open '.local/release/Mac/Codex Pool Widget.app' --args --preview
```

需要 Xcode Command Line Tools。脚本生成当前 Mac 架构的 `.app`，使用本机 ad-hoc 签名，尚未提供公证或发行签名。

**当前交付是 Mac 客户端源码与预览入口，未通过 Mac 编译或真机验收；现有 Daemon 仍依赖 Windows DPAPI，不能直接在 Mac 上运行。** 完整 Mac 使用需要后续独立实现 Keychain 凭据存储、跨平台 Daemon 打包和真实账户验收。预览数据有明确标记，不能当成真实额度。

客户端已预留仅连接 `127.0.0.1:3210` 的 Local API 对接。未来 Mac Daemon 与 `.app` 相邻放置于 `Mac/Daemon/CodexPool.Daemon`，或设置 `CODEX_POOL_DAEMON` 为本机可执行文件绝对路径。客户端通过 Daemon `model-credential` 的私有 stdout 管道读取本地控制 key，不读取 OAuth、不会记录 key、不写入偏好文件；请求禁用代理与重定向。真实连接每 3 秒更新状态，离线时禁止切换。点击切换由 Daemon 负责 sticky 调度。

Windows 无法直接运行 SwiftUI/AppKit 原生 `.app`。可以在当前 Windows 小组件上确认同类卡片布局和操作流程；Mac 材质、菜单栏、多显示器和系统行为需要真实 Mac 测试。当前原型也没有注册为 macOS WidgetKit 桌面组件。

## 验收边界

**ChatGPT Desktop** 经 Codex Pool 发送的端到端验收仍待完成（与 CLI/app-server 原生验收分开）。

Windows：构建、真实代理状态/额度显示、隐藏启动、快捷键展开、启动器单实例唤醒、打开浮窗后收起已验证。原代理持续运行，未更改额度阈值或 Codex 配置。手动 Radio 切换/自动切换同步、真实托盘鼠标操作、多显示器和长期离线重连还需进一步验收；账户迁移仍以独立真实验收报告为准。

Mac：当前 Windows 环境仅能审查源码和构建脚本，原生编译、材质与生命周期未验证。

## 托盘右键菜单

托盘图标右键改为与面板同主题的 WPF 玻璃弹出菜单（`GlassTrayMenu`）已通过 [PR #8](https://github.com/AliceJump/codex-muti/pull/8) 合入 `master`，保留六项：显示账户面板、固定/取消固定面板、打开 Dashboard、刷新额度、任务栏图标显示设置、退出托盘面板。`StableTrayIcon` 的 GUID（`552bb14d-21b7-4a30-aed2-641f1fd39422`）升级时保持不变，避免 Windows 丢失托盘可见性偏好。

当前 16 项 UI 回归通过，覆盖动态额度、Token 未报告、过期/重置、离线禁用、空池、多账户滚动、读屏帮助、按钮 Invoke、快速反向、动画期间状态更新及固定/取消固定的失焦行为；实际 HWND 在六向三态切换及屏幕边缘的快速反向展开中没有新增 WM_SIZE；边缘纠正只发生在状态更新时，帧间 HWND 位置保持不变。尺寸与输入回归不能代替真实画面帧率验收，混合 DPI、显示器切换和真实背景模糊仍需单独确认。

## 分组件部署

双击 `deploy.cmd` 选择“仅部署桌面组件”，或执行 `deploy.cmd Components`，更新账户托盘面板和已经运行的独立代理托盘，两个图标使用同一构建，启动时不展开卡片或右键菜单；核心进程保持原样，即使核心未运行也不会由这次组件更新自动启动。选择“仅部署核心”则保留现有 UI。首次部署请选择全部。脚本分离构建和替换，只替换所选进程，所选部分失败时尝试恢复原版本。

开发验证入口：`pwsh -NoProfile -File scripts/tests/deployment-targets.ps1`。该测试在主仓忽略的 `.research/` 下模拟发布、启动和故障，不操作真实代理、UI 或账户。
