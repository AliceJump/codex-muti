# 额度与 Token 统计

额度沿用各原生注册的官方 usage 快照，按实际秒数动态显示窗口时长、剩余百分比、重置时间和更新时间。例如 5h、7h、9h、90m、周或其他秒数，不把 primary 固定当成 5h。超过 2 分钟、时间异常、缺少重置时间或已过重置点的窗口显示待确认；Web、悬浮窗、胶囊和托盘采用相同有效期。额度百分比独立于 Token 用量，不按 Token 估算套餐剩余额度。

## 动态额度窗口

Web 提供一个「额度窗口使用阈值」，适用于所有时长；CLI 使用 `pool.ps1 settings on 95`。旧配置中的 5h／周阈值在用户保存新配置前保留，对其他时长使用两者较小值，保存新阈值后统一使用新值。旧 CLI 三参数形式仍可读取和设置原阈值。

基础 `rate_limit`、`credits` 和 `spend_control` 分开记录。接口明确允许使用或显示 credits 可用时，不单凭基础窗口达到 100% 判为账户耗尽；支出限制达到仍阻止后续请求。credits 是上游独立余额，不由 token 合计换算，代理不修改上游的付费使用设置。

上游明确允许使用但未提供窗口时显示「未提供固定额度窗口」；缺失、异常或过期数据显示未知，不将窗口缺失解释为无限。`credits.unlimited` 仅表示上游 credits 字段的状态，不保证所有模型或所有限额无限。

附加限额保持独立身份并展示。只有上游明确提供 `normal_model_slug`／`normal_model` 与当前请求模型一致时，附加窗口才参与该模型的调度；缺少模型关系的附加窗口展示在面板，不推断为全账户限制。额外未知字段不会改变请求重放边界，现有明确上游拒绝处理仍保留。

托盘数字显示当前已知账户级窗口中最少的剩余百分比；模型专属额度显示在面板。完整、紧凑和胶囊布局都动态展示窗口，数据更新时自动移除已消失的窗口。macOS 原型也更新了字段与标签，但本机 Windows 环境没有进行 Swift 编译／真机验收。

动态窗口扩展通过 Core 33/33、凭据与统计 29/29、隔离 Local API 1/1、原生 UI 10/10；新增覆盖任意时长、第三个窗口、相同时长的独立控件、窗口重置后的旧拒绝状态失效、无窗口／credits／预算限制和模型作用域。部署校验将旧版本省略的可选阈值归一化为 null，同时仍检测真实设置变化。任意新时长与 credits 的真实账户验收尚未完成。

Web 的「Token 用量」默认显示全部历史，可切换今日、最近 7 天、最近 30 天，或输入开始／结束日期。时间范围同时作用于账户／模型汇总、每日趋势和请求历史。日期按代理主机时区解释，起止日期均包含当天；只填写一端表示单边筛选。请求历史每页 100 条，可继续加载更早记录，完整日期时间区分不同天的请求。

状态事件和倒计时只更新变化的文字、额度进度和行属性，按账户 ID、额度窗口、请求序号等复用已有 DOM，不重新替换整块账户池或统计表格。后台请求历史更新保留原内容直到响应到达，合并新记录并保留已加载的旧页、分页游标和可见行位置；改变日期范围时才清空并重新查询。设置表单的未提交输入、按钮焦点与列表滚动不因状态事件重置。

增量更新回归：先将 `jsdom@26.1.0` 安装到主仓忽略目录 `.research/dashboard-dom`，设置 `NODE_PATH` 指向其 `node_modules`，再运行 `node --test scripts/tests/dashboard-updates.test.cjs`。用例覆盖相同快照不修改账户 DOM、额度及事件处理器更新、表格节点和输入焦点保留、后台历史合并、旧分页游标保留及筛选请求的乱序响应。

历史请求、输入／输出 Token、缓存／推理明细和账户切换记录保存在本地，关闭代理后再次启动仍可查看。不会按 7 天或 90 天自动删除。每日趋势只展示有记录的日期，长期列表可以滚动查看。

```powershell
.\scripts\pool.ps1 statistics
.\scripts\pool.ps1 statistics 2026-01-01 2026-10-19
.\scripts\pool.ps1 requests 2026-01-01 2026-10-19
```

本地鉴权的 `GET /statistics?from=yyyy-MM-dd&to=yyyy-MM-dd` 返回筛选范围的 `selected` 汇总与 `daily` 趋势，同时保留 `today / last7Days / allTime`。`retainedDays=null` 表示不自动过期；`earliestDailyDay` 给出最早仍有日汇总的日期。`GET /requests` 接受相同日期参数，支持 `limit`（1–200，默认 100）和 `before` 游标；响应 `nextBefore` 为空时已到最后一页。非法日期、倒置范围、重复参数及非法分页返回 400。

`GET /status` 及 `/events` 提供统计概览、最近 100 条请求和最近 100 条切换。概览不携带完整日趋势，详细历史按需从查询接口读取。本地网页直接读取，本地访问密钥也可读取，官方模型入口的凭据不能访问历史控制接口。原有 `/usage` 继续返回各账户真实额度快照。

## 统计口径

- 只记录经过本代理、已经进入模型传输的 HTTP 请求。从新版本启用后开始，不能回补历史或统计其他客户端直接访问上游的用量。刷新额度、读取模型目录和请求准入前失败不计入请求数。
- 每次代理请求结算一次。安全切号后归属实际上游账户；被明确拒绝的前置尝试不重复计入请求数。同一请求内重复 usage 事件只取第一份有效终态用量。客户端重新发起的独立请求分别计数。
- 只读取 `response.completed`、`response.incomplete` 或 `response.failed` 终态 Response 的有效 `usage`。不累计 delta，不用 EOF 或文本长度推算。最大观察事件为 2 MiB，超限事件不改变转发内容，缺少可验证 usage 的用量显示未报告。
- `input_tokens`、`output_tokens`、`total_tokens` 必须为非负整数，且总量与输入＋输出一致。缓存是输入子集，推理是输出子集，均不再加入总量；可选明细缺失或无效时保留未知。字段依据 [OpenAI Responses streaming events](https://developers.openai.com/api/reference/resources/responses/streaming-events) 与 [Counting tokens](https://developers.openai.com/api/docs/guides/token-counting)。
- 上游已经发送完整终态 usage，即便对应下游写入失败也记录报告的消耗。中断、取消或失败时没有完整 usage，则请求数增加、Token 用量未知。未报告请求及明细覆盖数单独显示；部分覆盖下展示的是已报告部分的合计。
- 日期按代理主机的本机时区、请求结算时间划分；最近 7 天为今天及前 6 个自然日。接口显示时区。日桶、累计桶和新请求明细长期保留，删除账户后历史保留并显示「已移除账户」。统计模型是请求中的 model 名称，不把它当作计费型号或金额。

## 存储

统计写入 Daemon 数据目录下独立的 `usage.sqlite`。SQLite 事务同时保存请求明细与日／累计计数，WAL 模式和 FULL 同步确保成功提交后可以在下次启动恢复；不重写账户凭据文件。账户、模型、状态、耗时、尝试次数、Token 数值及切换事件载荷使用 Windows DPAPI CurrentUser 加密，数据库只以明文索引日日期、内部序号和散列桶键。目录沿用 Vault 的当前用户 ACL。

不保存 prompt、响应正文、工具参数／结果、Response ID、授权信息或上游错误正文。每个进入模型传输的请求在结算时立即尝试提交；写入失败保留内存队列，每 2 秒重试，并在正常关闭时再次保存，页面显示等待保存。保存失败期间强制退出仍可能丢失待保存记录。

首次启用时自动迁移旧 `usage.dpapi` 中仍存在的日汇总和累计值，迁移与完成标记在同一事务中提交，重启不会重复导入；旧文件保持原样。旧版已经清理的日汇总和从未落盘的请求明细无法回补，累计仍保留。页面分别显示最早日汇总和请求明细开始时间。

历史无法读取或解密时显示历史不可用，保留原历史并停止写入，当前运行期的新数据只存在内存中。不要在代理运行时手工移动数据库；备份应在代理正常退出后复制数据目录，或使用 SQLite 在线备份机制。DPAPI 数据仅能由同一 Windows 用户解密。

## 验证范围

合成测试覆盖加密持久化与重启恢复、旧版统计一次性迁移、跨本地午夜、400 天前数据保留、请求游标分页、无 usage 请求、1000 个并发结算、写入失败重试，以及非法日期与分页。模型转发的安全重试边界、上游 usage 解析与原生 UI 仍由原有回归覆盖。

本次 solution 构建为 0 警告／0 错误；Core 34/34、Security 42/42 和隔离端口 Local API 1/1 通过；部署隔离脚本 17/17 通过。合成浏览器验收覆盖 205 条请求的三页加载、超过一年的日期筛选、代理与浏览器时区不同、快捷时间范围和窄屏布局。原生 UI 两次运行均为 22/23，但失败分别落在未改动的托盘动画／点击时序断言，不能标记整套原生 UI 通过。

这些测试不能证明真实账户的 Token 报告完整性、缓存命中或跨账户计费行为。只统计经过本代理的模型请求，未经过代理或旧版未保存的数据无法恢复。
